# The native Cortex Analyst evaluation cannot grade a refusal (2026-10-12)

**Claim discussed (paraphrased):** Snowflake now ships a native evaluation for Cortex Analyst, so you no longer need
your own test pack for the analyst.

**What the documentation says** ([Cortex Analyst evaluations](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst-evaluations), fetched 2026-10-12):

> "Cortex Analyst evaluations use verified queries (VQs) as the evaluation set."

> "Each verified query pairs a natural language question with its expected SQL answer."

> "Evaluations measure accuracy by executing the SQL generated by Cortex Analyst and comparing the results against your verified queries."

> "sql_correctness is the only supported metric for Cortex Analyst evaluations."

> "No auto-generated evaluation datasets : Evaluation sets must be manually curated from verified queries."

**What I tested:** the ten questions of `seeds/question_pack.csv` against the verified-query table that
`scripts/run_native_eval.py` would load (its `EXPECTED` dict: one expected SQL per question). Fictional data.
No Snowflake call: the native evaluation has not been run; this proof is about what can enter the evaluation set.

| | Questions |
|---|---|
| Gradable (have an expected SQL) | 9 of 10 (Q01-Q09) |
| Refusal questions (`expect_refusal = true`) | 2 (Q06, Q10) |
| Excluded: right answer is a refusal on an undefined metric | 1 (Q10 churn) |

**Result:** the claim fails for refusals. Q10 ("What is our customer churn rate?") is on a metric the registry marks
`undefined`; its correct answer is a refusal, and a refusal has no expected SQL, so it cannot be a verified query and
never enters the evaluation set. The only metric is SQL correctness, so a run that scores 9 of 9 says nothing about
whether the analyst refuses churn. Q06 stays in the set only because its "undefined" answer is a SQL NULL (division by
zero sessions); the grader compares that result, not whether the analyst declined. Refusals still need their own test
(see `2026-10-09-refusal-text-is-not-a-refusal`).

**What the script checks (`check.sh`):**
1. counts the verified queries in `scripts/run_native_eval.py` against the pack: 9 gradable, 1 excluded;
2. every excluded question is a refusal question, and no question on an `undefined` metric carries an expected SQL;
3. mutation: a copy where Q10 is given a fake expected SQL (`SELECT 0.12`) must go RED.

Run: `bash proofs/2026-10-12-native-eval-cannot-grade-refusal/check.sh`. Final line `NUMBERS: ...`.
